# Independent payment window and driver hold

Prepared locally from `ops/local-guide-web-20261022` at `e84e33da018375230bfaee26bf4c7ec633d9bf9d`. No VPS change, remote branch, release or payment has been performed for this change.

New passenger bookings reserve an eligible driver exclusively for 60 seconds and have a separate 600-second checkout deadline. No driver offer is sent before payment. The existing reservation comparisons already release eligibility at `reserved_until <= now`; expired metadata does not continue excluding the driver and must not be rewritten to make old GPS look fresh. Another passenger can reserve that driver after 60 seconds. A confirmed payment within the checkout window follows the existing dispatch path: it prefers the original reservation only while that reservation is active, and otherwise ranks currently online/available drivers with fresh GPS, correct category, capacity, radius and compliance. The prepared fare remains unchanged.

An additive nullable `rides.payment_expires_at` column persists the independent deadline. It is included in preparation, creation, reads, saves and matching projections. Historical rides without the new field keep the existing deadline behavior. Consent-before-payment bookings also keep their original driver hold, even if a checkout field is present.

Payment creation for card/Pix, wallet, cash authorization, free promotional payment and late external confirmation use checkout expiry rather than exclusive-driver-hold expiry. Invalid deadlines fail closed. Late external confirmation after the checkout deadline retains the existing refund path. No-driver dispatch retains cancellation/retry and the existing automatic timeout refund, rather than silently retaining funds.

Coupon reservations now last until the checkout deadline. The legacy response field `holdExpiresAt` remains the checkout deadline for compatibility with shipped clients; `paymentExpiresAt` and `driverReservationExpiresAt` make the distinction explicit for new clients. Flutter parsing and payment/card/Pix wording now describe the time to pay rather than claiming a driver remains reserved for ten minutes. The ADM clarifies that its pre-acceptance flow hold setting does not control the new fixed 60-second initial reservation.
